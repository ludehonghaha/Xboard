# XBoard Lite v3 — 功能盘点与重构范围

目标：保持 XBoard / Xboard-Node 的核心节点运营能力完整，同时彻底去除不需要的商业化模块。
原则：先盘点、再展示、最后删除；未经确认不再因为“瘦身”隐藏核心能力。

## 1. v3 产品形态

- 单一 Lite Portal：管理员与普通用户共用一套前端，不恢复旧版双前端。
- 管理员登录后看到管理功能；普通用户只看到订阅与账号相关功能。
- 保留 XBoard 后端成熟的数据模型、订阅生成、节点协议和 Machine Agent。
- 生产数据结构不重建，升级必须沿用现有 SQLite 数据库。
- 不以“文件越少”为目标；以“业务模块少、核心能力完整”为目标。

## 5. 已经删除，不应恢复的商业模块

以下属于原 XBoard 商业面板能力，Lite v3 不恢复：

- 商城 / 套餐购买页
- 订单
- 支付网关
- 优惠券
- 佣金 / 返佣 / 邀请返利
- 工单
- 商业公告/营销通知
- 邮件注册验证
- 密码邮件找回
- 免费试用
- 充值/余额体系
- 商业支付统计

## 6. 前端重构规则

v3 不再按“页面少”删除业务能力，而是合并信息架构。

管理员侧：
1. 概览
2. 用户
3. 套餐与权限
4. 服务器
5. 节点
6. 路由
7. 流量与统计
8. 邀请码
9. 系统设置
10. 可选扩展（仅用户确认后保留）

普通用户侧：
1. 我的订阅
2. 使用情况
3. 账号与登录会话
4. 可选：Telegram / 知识库 / 礼品卡（取决于最终决定）

## 7. 删除规则

只有满足以下全部条件才物理删除代码：

1. 用户明确确认“不需要”；
2. 不被保留模块依赖；
3. 数据库字段/迁移不会破坏现有生产数据；
4. 删除后订阅生成和 Xboard-Node 不受影响；
5. 删除前有数据库和 Git 备份。

如果只是暂时不需要但存在潜在依赖，先从 UI/路由隔离，不立即删模型/迁移。
